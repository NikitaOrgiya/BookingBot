# Чеклист развёртывания BookingBot для нового клиента

Общий порядок действий при установке BookingBot для нового заказчика.
Ниже — только шаги и переменные окружения без значений; реальные
значения текущего production-проекта в этот файл не помещаются.

## 1. Telegram-бот

- [ ] Создать нового бота через [@BotFather](https://t.me/BotFather).
- [ ] Получить токен бота и username бота.
- [ ] Сгенерировать собственный секрет вебхука (1–256 символов,
      `A-Za-z0-9_-`).

## 2. Supabase project

- [ ] Создать новый Supabase-проект для этого клиента (не переиспользовать
      чужой production-проект).
- [ ] Получить URL проекта, publishable-ключ и secret-ключ.
- [ ] Убедиться, что расширения `pg_cron` и `pg_net` доступны в проекте.

## 3. Vercel project

- [ ] Создать новый Vercel-проект, подключённый к репозиторию.
- [ ] Настроить домен production-окружения.

## 4. Переменные окружения (только имена, без значений)

- [ ] `NEXT_PUBLIC_SUPABASE_URL`
- [ ] `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
- [ ] `SUPABASE_SECRET_KEY`
- [ ] `NEXT_PUBLIC_APP_URL`
- [ ] `TELEGRAM_BOT_TOKEN`
- [ ] `TELEGRAM_BOT_USERNAME`
- [ ] `TELEGRAM_WEBHOOK_SECRET`
- [ ] `CRON_SECRET`

Все значения задаются напрямую в Vercel Environment Variables (Production)
и в локальном `.env.local` для разработки — никогда не коммитятся в
репозиторий.

## 5. Применение миграций

- [ ] Применить все миграции из `supabase/migrations/` к новому проекту
      по порядку (в правильной среде выполнения — не через `db reset`,
      который предназначен для локальной/тестовой базы).
- [ ] Убедиться, что список применённых миграций совпадает с локальной
      историей миграций репозитория.

## 6. Создание первого администратора

- [ ] Создать пользователя в Supabase Auth (email + пароль или
      приглашение).
- [ ] Добавить его `UUID` в таблицу `admin_users` через доверенное
      подключение (не через саму панель — публичного UI для этого нет).

## 7. Business settings

- [ ] Заполнить название организации, часовой пояс (настоящий
      IANA-идентификатор), горизонт бронирования, сроки уведомления и
      отмены, шаг слотов, параметры напоминаний (за сколько минут
      присылать 24-часовое и 2-часовое напоминание).

## 8. Услуги

- [ ] Создать реальный каталог услуг клиента (название, длительность,
      цена).
- [ ] Деактивировать или удалить демонстрационные услуги, если они были
      предзаполнены.

## 9. Расписание

- [ ] Настроить недельные рабочие интервалы.
- [ ] Добавить известные заранее разовые блокировки (отпуск, праздники).

## 10. Установка Telegram webhook

- [ ] Убедиться, что production-домен доступен по HTTPS.
- [ ] Зарегистрировать webhook на `https://<домен>/api/telegram/webhook`
      с секретом из шага 1.
- [ ] Зарегистрировать список команд бота.
- [ ] Проверить `getWebhookInfo` — webhook активен, нет накопленных
      ошибок доставки.

## 11. Настройка Supabase Vault (для напоминаний)

- [ ] Создать в Vault секрет с production-URL cron-эндпоинта
      (`https://<домен>/api/cron/reminders`).
- [ ] Создать в Vault секрет со значением `CRON_SECRET` этого клиента
      (то же значение, что задано в Vercel Production).
- [ ] Никогда не выводить значения секретов в чат, логи или отчёты.

## 12. Активация Supabase Cron

- [ ] Выполнить подготовленный ops-скрипт создания cron job (стабильное
      имя, расписание, без литеральных секретов в тексте команды —
      секреты резолвятся из Vault на каждый запуск).
- [ ] Убедиться, что job создан ровно один раз (без дублей) и активен.
- [ ] Дождаться первого автоматического запуска и убедиться, что он
      завершился успешно, а HTTP-вызов эндпоинта вернул успешный статус.

## 13. Production smoke-test

- [ ] Пройти полный клиентский сценарий в Telegram: `/start` → выбор
      услуги → дата → время → подтверждение → запись создана.
- [ ] Проверить `/mybookings` и отмену записи.
- [ ] Войти в административную панель под созданным администратором.
- [ ] Убедиться, что новая запись видна в панели.
- [ ] Проверить cron-эндпоинт: без авторизации — отказ, с верным
      секретом — успешный ответ, без раскрытия персональных данных.
- [ ] Дождаться (или создать контролируемым образом) реальную доставку
      одного напоминания и убедиться, что повторной отправки не
      происходит.

## 14. Rollback (откат)

- [ ] Знать, как остановить Supabase Cron (отдельный ops-скрипт
      отключения job) без удаления самих секретов или данных.
- [ ] Знать, как откатить Vercel-деплой до предыдущей рабочей версии
      через интерфейс Vercel.
- [ ] Помнить, что миграции применяются только вперёд новыми файлами —
      откат схемы делается отдельной корректирующей миграцией, а не
      редактированием уже применённых файлов.

## 15. Резервное копирование

- [ ] Убедиться, что для Supabase-проекта клиента включено регулярное
      резервное копирование (управляется на стороне Supabase, в
      зависимости от плана проекта).
- [ ] Задокументировать для клиента, кто отвечает за проверку резервных
      копий и как выполнить восстановление в случае необходимости.
